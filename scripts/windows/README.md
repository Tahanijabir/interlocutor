
# Building and Testing Opus on Windows

This guide documents how to build the native Opus codec from
source on Windows using MSYS2 UCRT64 and verify that it works
with Python's `opuslib-next` package.

The procedure does not require downloading a prebuilt Opus DLL
from an unofficial source.

**Scope:** This guide validates the Opus codec dependency only.
Full Windows compatibility of the Interlocutor application has
not yet been established.

## Requirements

- Windows x64
- MSYS2 UCRT64
- GCC, CMake, Ninja, and Git
- Python with virtual environment support
- Python package: `opuslib-next`

### Install build tools

Open the MSYS2 UCRT64 terminal and update the package database
and installed packages:

```bash
pacman -Syu
```

If MSYS2 requests a terminal restart, close the terminal,
reopen MSYS2 UCRT64, and finish any remaining updates:

```bash
pacman -Su
```

Install the required build tools:

```bash
pacman -S --needed \
  mingw-w64-ucrt-x86_64-gcc \
  mingw-w64-ucrt-x86_64-cmake \
  mingw-w64-ucrt-x86_64-ninja \
  git
```

Run the following build commands in the MSYS2 UCRT64 terminal.

## 1. Build native Opus

Clone the official Xiph.Org Opus repository:

```bash
git clone https://github.com/xiph/opus.git
cd opus
```

For reproducibility, check out the commit used during the
initial Windows validation:

```bash
git checkout 677070ed
```

Configure a Release build with shared-library support:

```bash
cmake -S . -B build-windows -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_SHARED_LIBS=ON
```

Build the library:

```bash
cmake --build build-windows --parallel 4
```

The build should produce:

```text
build-windows/libopus.dll
```

Keep the original DLL filename. The Python bootstrap provided
with this guide accepts the full path to `libopus.dll`.

## 2. Run upstream Opus tests

Configure a separate static build with testing enabled:

```bash
cmake -S . -B build-tests -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_SHARED_LIBS=OFF \
  -DOPUS_BUILD_TESTING=ON
```

Build the test targets:

```bash
cmake --build build-tests --parallel 4
```

Run the upstream tests:

```bash
ctest --test-dir build-tests --output-on-failure
```

During the initial Windows validation, all five upstream Opus
tests passed.

Test results may vary with the compiler, dependencies, and
Opus revision.

## 3. Prepare the Python environment

Open Windows PowerShell in the Interlocutor repository.

Create a virtual environment:

```powershell
python -m venv .venv
```

Install the Python Opus binding:

```powershell
.\.venv\Scripts\python.exe -m pip install opuslib-next
```

The package `opuslib-next` provides Python bindings but still
requires a native Opus library.

On Windows, its library discovery may not find the
`libopus.dll` generated by the MSYS2 build automatically.

The provided bootstrap addresses this discovery issue by
accepting an explicit DLL path.

## 4. Verify Opus on Windows

Set the DLL and dependency directory paths to match your
installation:

```powershell
$OpusDll = "C:\path\to\opus\build-windows\libopus.dll"
$UcrtBin = "C:\msys64\ucrt64\bin"
```

Run the verification suite:

```powershell
& ".\.venv\Scripts\python.exe" `
  ".\scripts\windows\opus_bootstrap.py" `
  --opus-dll $OpusDll `
  --dll-dir $UcrtBin `
  ".\scripts\windows\verify_opus.py"
```

The `--dll-dir` option makes the MSYS2 UCRT64 runtime
dependencies available to the Python process.

The bootstrap does not require modifying the system-wide
Windows PATH or renaming the native Opus DLL.

### Expected test results

Successful execution should report three passing test methods,
with output similar to:

```text
test_audio_signals ... ok
test_codec_configurations ... ok
test_continuous_stream ... ok

----------------------------------------------------------------------
Ran 3 tests

OK
```

The number of test methods is three, but each method may
exercise multiple test cases through Python's `unittest`
subtest mechanism.

### Test coverage

The verification suite includes:

- Silence encoding and decoding
- 440 Hz and 1800 Hz test tones
- Deterministic noise input
- 16 kHz and 48 kHz sample rates
- 20 ms and 40 ms audio frames
- Mono and stereo configurations
- Constant bitrate (CBR) and variable bitrate (VBR)
- Continuous processing of multiple audio frames using
  persistent encoder and decoder instances

The tests validate basic codec functionality, encoded packet
generation, decoded PCM length, and non-silent output for
non-silent test signals.

These tests do not measure perceptual audio quality.

## 5. Bootstrap behavior

The `opus_bootstrap.py` script:

1. Validates the supplied DLL and script paths.
2. Adds the requested DLL directories to the current process.
3. Loads the native Opus DLL using `ctypes`.
4. Checks that an Opus version function is available.
5. Provides a process-local workaround for library discovery.
6. Executes the requested Python script with its arguments.

The workaround is intended to support testing and explicit
DLL loading without modifying installed Python packages.

The bootstrap may also be used to launch another Python script
that relies on `opuslib-next`, although successful operation
of that script requires its other dependencies to be available.

## Limitations

- Initially validated on Windows x64 using MSYS2 UCRT64
  and Python 3.13.
- Other Windows compiler toolchains have not been validated.
- The native Opus DLL may require runtime libraries from
  the compiler toolchain used to build it.
- The bootstrap uses a process-local override of
  `ctypes.util.find_library`.
- The workaround is not an upstream fix to `opuslib-next`.
- Tests validate basic encoding and decoding functionality,
  not perceptual audio quality or packet-loss resilience.
- Full Interlocutor execution has not been validated on
  Windows.
- Microphone access, GPIO functionality, and complete
  application-level integration are outside the scope
  of these tests.

## Validation summary

The initial Windows development environment successfully
completed:

- Native Opus shared-library compilation
- Five upstream Opus tests
- Python Opus encoder and decoder initialization
- Multi-configuration functional codec tests
- Continuous audio-frame processing
- Native DLL loading using an explicit path
- Error reporting for a missing DLL path

This provides a reproducible starting point for developers
investigating Windows Opus support in Interlocutor.
